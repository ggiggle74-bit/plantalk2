# CR-2V: 심층분석 횟수 차감 안전장치

## 목적

심층 건강분석이 성공했을 때만 사용 횟수를 확정하고, 실패·취소·mock 결과에서는 임시 사용 예약을 반환한다. 버튼 중복 입력이나 여러 기기의 동시 요청으로 남은 횟수를 초과하지 않도록 서버 예약 ID를 실행 경계로 사용한다.

## 생명주기

1. 서버가 사용자 권한과 남은 횟수를 확인한다.
2. 허용할 경우 고유한 `reservationId`를 발급하고 사용량을 임시 예약한다.
3. 사진 저장과 실제 심층분석을 실행한다.
4. 유효한 provider 결과와 메모리 저장이 끝나면 예약을 확정한다.
5. 중간 작업이나 확정이 실패하면 예약을 반환한다.

차단된 요청에는 예약 ID가 없어야 하며, 허용된 요청에는 비어 있지 않은 예약 ID가 반드시 있어야 한다.

## 유료 결과 정책

- `PlantConditionAnalysisResult.isMock`가 true이면 성공으로 처리하지 않는다.
- 정규화된 대표 이벤트의 `isMock`가 true여도 성공으로 처리하지 않는다.
- mock 결과에서는 메모리를 저장하거나 사용 횟수를 확정하지 않는다.
- provider 오류는 원래 오류를 보존한 채 예약을 반환한다.
- 예약 반환까지 실패하면 원래 오류와 반환 오류를 함께 보존한 복구 예외를 반환한다.

## 서버 구현 요구사항

향후 Supabase 구현의 예약·확정·반환 작업은 같은 요청이 반복돼도 결과가 달라지지 않는 멱등 연산이어야 한다.

- 이미 확정된 예약의 재확정: 성공 또는 현재 상태 반환
- 이미 반환된 예약의 재반환: 성공 또는 현재 상태 반환
- 확정된 예약에 대한 반환: 확정 상태 유지
- 만료된 임시 예약: 서버 정책에 따라 자동 반환
- 예약 ID는 인증된 사용자에게만 귀속
