# Camera C 식물 식별 Boundary 설계

## 목적

이 문서는 1차 카메라 등록 flow에서 사용할 `plant_identification` boundary를 설계하기 위한 문서다.

`plant_identification`은 식물 종류와 이름 후보를 찾기 위한 영역이다.

기존의 `plant_analysis`와 역할을 분리한다.

- `plant_identification` = 식물 종류 / 이름 후보 찾기
- `plant_analysis` = 기존 식물의 상태 / 건강 분석

두 역할은 섞지 않는다.

## 현재 상태

아직 실제 API를 연결하지 않는다.

이번 문서는 설계 메모만 남기는 단계다.

금지 사항:

- HTTP client 추가 금지
- API key 추가 금지
- Supabase schema 변경 금지
- main.dart 수정 금지
- 1차 카메라 등록 flow 수정 금지
- 대표 사진 동작 수정 금지
- 실제 외부 API 연결 금지

## 1차 카메라 등록 flow의 의미

1차 카메라 flow는 식물의 탄생 / 정체성 등록 flow다.

현재 보호해야 할 흐름:

1. 사진 선택 또는 촬영
2. 식물 종류 결정 또는 확인
3. 식물 별명 짓기
4. plant 생성
5. 대표 사진 저장
6. 채팅창 진입

이 flow는 아직 수정하지 않는다.

## 향후 API가 들어간 등록 flow

나중에 식물 식별 API가 들어가면 흐름은 이렇게 된다.

1. 사용자가 식물 사진을 선택하거나 촬영한다.
2. `plant_identification` boundary가 이미지를 받는다.
3. 식물 식별 adapter가 식물 이름 후보를 가져온다.
4. 앱이 사용자에게 후보를 보여준다.
5. 사용자가 맞는 식물을 선택하거나 직접 입력한다.
6. 사용자가 식물 별명을 정한다.
7. plant가 생성된다.
8. 대표 사진이 저장된다.
9. 채팅창으로 들어간다.

중요 원칙:

API가 식물 정체성을 자동 확정하면 안 된다.

반드시 사용자가 식물 종류를 확인하거나 직접 입력한 뒤 plant를 생성해야 한다.

## 사용자 확인이 필요한 이유

식물 식별 API는 틀릴 수 있다.

특히 실내식물은 잎 모양이 비슷한 경우가 많다.

예시:

- 스킨답서스 vs 필로덴드론
- 어린 몬스테라 vs 스킨답서스
- 산세베리아 품종 차이
- 고무나무 계열
- 다육식물 품종 차이

따라서 Plantalk의 원칙은 이렇다.

API는 후보를 제안한다.

사용자가 식물 정체성을 확정한다.

Plantalk는 사용자가 확정한 정체성을 기억한다.
